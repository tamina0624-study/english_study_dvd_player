1. 適用範囲・前提

仕様書v0.2と基本設計書v0.1を実装へ落とすための詳細設計。以下のクラス名・メソッド名・設定値は本アプリ用の設計であり、ライブラリの既存APIや実装済みのコードを意味しない。

  • 手持ちのドラマDVDに英語・日本語字幕が収録され、取得できる前提で進める。
  • 初版は字幕画像を一覧表示し、OCR・機械翻訳は行わない。
  • 字幕取得バックエンドの具体的な製品・ライブラリと呼出APIは未選定。共通契約を本書で定義する。トラック選択機能を字幕画像の取得機能として代用しない。

字幕バックエンドとの実接続は実装上の残課題。取得可能という前提の下で他の処理を独立実装できる設計にする。未接続のダミーデータを実DVDから取得した字幕として表示しない。

6. 再生制御・2秒戻しの詳細

読み込みと停止

ドライブを読み込み、タイトルを選択すると旧世代を無効化し、再生・字幕の状態を解除する。新タイトルの準備完了と0msへの位置設定を確認してREADYとする。停止ボタンと自然終端は、先頭へ戻してREADYにする。初期化のため内部的にエンジンが再生状態を経由する場合も、準備完了前にPLAYINGとして通知しない。

2秒戻し

on_rewind():
  if closing or not seekable or actual_position is None: return
  base = latest_requested_target if seek_pending else actual_position
  target = max(0, base - 2000)
  request_seek(target, preserve_original_state=True)

連続押下で10秒→8秒→6秒と要求位置を累積する。実エンジンへの位置要求は同時に1件とし、処理中に追加要求があれば最新の目標を1件だけ保持する。完了時に保留目標があれば次を送り、古い完了通知で表示を巻き戻さない。スライダーの絶対位置要求は保留目標を置き換える。

位置要求の完了判定

アダプターは位置変更イベント／実時刻を確認して完了を通知する。暫定で要求位置との差500ms以内、または到達確認後に再生が進んだと判定できる場合を成功とし、境界・キー位置依存の挙動を実機で調整する。監視タイムアウトは暫定5秒。目標値を実測位置として表示しない。タイムアウト時はエンジンの現在位置を再取得し、保留要求を解除して警告する。

位置変更の開始前にPLAYING / PAUSED / READYを保存し、最後の要求完了時に復元する。処理中の再生／一時停止操作は復元先状態を更新する。停止・タイトル変更・終了は位置要求を取り消す。チャプター移動も同じ排他制御と状態保持を使う。

READYでシークした場合は移動先で待機状態を維持し、停止操作は0msへ戻す。映像の位置精度は媒体とエンジンに依存するため、2秒戻しの計算値と実際の到達位置は別に記録・検証する。

7. 字幕処理アルゴリズム

トラックの選択・取得

  1. 字幕トラックを列挙し、言語コードをen / ja / undへ正規化する。
  2. enとjaそれぞれ最初のトラックを初期選択。undは番号付きで表示し、利用者が言語タブに割り当てられるようにする。
  3. キャッシュが一致すればロードする。未完了キャッシュは表示可能な範囲だけ使い、取得を再実行してcue_idで統合する。
  4. 両言語の取得をバックグラウンドで順次処理する。選択言語を優先し、DVDへの読み出しを並列に増やさない。再生との競合で遅延する場合は取得頻度を下げる。
  5. 取得画像を必要部分へ切り出し、透明度・パレットを反映したPNGとして扱う。タイトル先頭を0msとする時刻へ変換する。

原時刻の単位・原点・DVD内の連結区間はバックエンドで正規化し、同じエピソードの再生時刻と対応付ける。終了時刻不明の字幕は勝手な長さを付けず、バックエンドの表示終了情報で確定する。取得不能なデータは行単位でエラーとし、走査済み範囲から除外する。

同期と重複区間検索

トラックごとに(start_ms, end_ms, cue_id)でソートし、開始時刻の配列と終了時刻の累積最大値を保持する。時刻t以下で始まる最後の位置を二分探索し、後方へ走査する。終了時刻の累積最大値がt以下になれば、それ以前に有効な字幕はないため打ち切る。各行はstart_ms ≤ t < end_msで判定し、該当する全行を返す。通常の重複は保持し、同じcue_idの再受信だけを更新する。

sync(t, track):
  if t is None: clear_highlight(); return
  if not coverage_contains(t): show_loading_at_position(); clear_highlight(); return
  active = repository.active_at(track, t)
  highlight(active)
  if follow and active: scroll_to(first_active_row)

GUIのタイマーは暫定100ms。シーク・タイトル準備・言語切替・batch追加後は即時再評価する。現在cue_id群が変わらない場合は強調表示を更新しない。手動スクロールは追従だけ解除し、同期は継続する。空白区間は強調なし、取得済み範囲外は取得中、完了後の0件は字幕なしを表示する。

代替取得

直接取得に問題がある場合は事前処理方式のSubtitleSourceへ差し替える。読み込むデータは同じ正規化済み字幕・coverage契約に適合させる。媒体・タイトル・トラックの一致を検証し、単なるファイル名の一致では採用しない。実際の事前処理ツールは問題発生時に選ぶ。

8. キャッシュ形式・ファイル処理

保存先はWindowsユーザーのローカルアプリデータ領域配下 dvd_player/cache/{media_id}/{title_id}/{track_id}/。具体的なユーザー名を設定へ埋め込まない。manifest.jsonとimages配下のPNGで構成する。DBは使わない。

{
  "schema_version": 1,
  "media_id": "example-media",
  "source_fingerprint": "example-fingerprint",
  "title_id": 1,
  "track_id": "subtitle-0",
  "language": "en",
  "complete": false,
  "coverage": [{"start_ms": 0, "end_ms": 30000}],
  "cues": [{
    "cue_id": "cue-000001",
    "start_ms": 12000,
    "end_ms": 14500,
    "image_path": "images/cue-000001.png"
  }]
}

上記は形式説明用の仮データ。complete=trueは当該タイトル・トラックの走査と整合性確認が完了した場合だけ保存する。字幕の空白時間もcoverageへ含め、隣接区間は統合する。

  • 媒体識別はドライブ文字やラベルではなく、タイトル構造・DVD管理情報等のフィンガープリントを用いる。ハッシュ化の入力仕様はバックエンド選定時に固定し、算出できない媒体は永続キャッシュを再利用しない。
  • 保存は画像の一時書込→置換→manifestの一時書込→置換。manifestは存在確認できた画像だけ参照する。
  • 読込時にschema、識別情報、型、時刻、cue_id一意性、画像存在、画像寸法を検証。不正データはキャッシュミスとして再取得する。
  • image_pathは相対パスのみ。解決後のパスがトラックのキャッシュ内にあることを検証し、外部参照を拒否する。
  • 暫定読込上限はmanifest 20MiB、1トラック100,000cue、画像4096×4096画素。超過時は無条件読込せず、キャッシュを無効化して通知する。実媒体の測定後に調整する。
  • メモリ画像はLRU方式、暫定64MiBを目安とし、画面に必要な画像を優先。1枚が上限を超える場合は表示サイズへ縮小する。ファイル全体を起動時に展開しない。
  • 初版はディスクキャッシュを自動削除しない。保存失敗時は通知して永続化を停止。再取得による一時データは終了時に破棄する。キャッシュ削除の手順はREADMEに記載する。

9. 非同期・取消・終了

GUI更新はGUIスレッドのみ。DVD走査と字幕取得はワーカーで実行する。ワーカーは中止トークンを処理単位ごとに確認し、画像デコード・ファイル書込の境界でも確認する。ブロックする外部処理はタイムアウトや中断可能な方式でアダプターを実装する。

on_title_change(new_title):
  generation += 1
  cancel_old_workers_and_position_requests()
  clear_subtitles_and_playback_view()
  prepare_title(new_title, generation)

on_result(result):
  if closing or result.context != current_context_for_result: return
  apply_validated_result(result)

トラックごとのcontextを照合し、再取得時も要求IDを更新して旧要求を無効にする。キャンセルは即時完了を仮定せず、遅れて返った結果を反映しない。媒体へのアクセスはワーカー終了前に解放しない。

終了シーケンス

  1. CLOSINGへ移行し操作を無効化。世代を更新して後続通知を拒否。
  2. タイマー停止、位置要求取消、字幕取得へ中止要求、再生停止。
  3. GUIを動かしたままワーカー終了を待つ。暫定5秒を超えたら「終了処理中」を表示し、アダプターの安全な中断を要求する。
  4. ワーカー完了後に媒体・VLCを解放し、終了する。

Pythonスレッドを強制終了して共有資源を解放しない。中断不能なバックエンドを選ぶ場合は別プロセス化し、終了手順を追加する。アプリが応答しない待機にならないことを実機で確認する。

10. エラーコード・ログ・回復

コード処理回復
ENV_MISSING依存ライブラリ・VLCが利用不可。再生操作を無効化。不足要素を案内し、環境修正後に再起動。
DRIVE_UNAVAILABLE / MEDIA_MISSINGドライブまたは媒体なし。EMPTYへ。再列挙・再読み込み。
MEDIA_UNSUPPORTED / PLAYBACK_FAILED再生停止。ERRORへ。未確認の原因を断定しない。媒体・タイトル再選択。
POSITION_FAILED / POSITION_TIMEOUT保留位置要求を解除し、実際の位置・状態へ復帰。通知後、再操作可能。
SUBTITLE_FAILED該当トラックをFAILED。映像・他言語は継続。再取得。必要なら代替方式。
CACHE_INVALID / CACHE_WRITE_FAILED破損キャッシュを採用しない。保存失敗はメモリ表示へ。再取得・保存先確認。
MEDIA_REMOVED取得・再生を中止。字幕解除後EMPTYへ。挿入後に再読み込み。

利用者には原因の区分と次の操作を表示し、内部例外の生文字列をそのまま出さない。ログはユーザー別アプリデータのdvd_player/logsへ保存。暫定1ファイル2MiB・3世代でローテーション。時刻、レベル、エラーコード、操作名、要求ID、タイトル番号を記録する。字幕・画像・秘密値・個人名を含むパスは記録しない。ファイル保存不能の場合は画面通知のみで続行可能とする。
